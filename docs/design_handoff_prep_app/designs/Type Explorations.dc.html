How does the framework know when a value has changed?

It compares the value it rendered last time with the value it sees now. That walk over the tree is called change detection, and everything about performance here is a question of how much of the tree it has to visit rather than how fast any single comparison is.

The default strategy checks every component on every pass, which is cheap until the tree is deep. Narrowing the checked surface — through immutable inputs, OnPush, or reading a signal the renderer can track — turns a whole-tree walk into a handful of visits, and that is the difference you feel on a long list.

count = signal(0);
double = computed(() => this.count() * 2);
